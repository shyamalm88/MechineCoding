Sliding Window

1. How to Spot This Pattern

1. Is it about a CONTIGUOUS subarray / substring?
No → not sliding window (think subsets, DP, backtracking).   Yes → continue.
2. Is the window's value MONOTONIC as it grows/shrinks (no negatives)?
No → sliding window breaks (think Kadane's / DP).   Yes → continue.
3. Is the window SIZE given (k, or len(pattern))?
Yes → Fixed-size window: slide it, compute per position.   No → Variable-size, continue.
4. Are you asked for LONGEST or SHORTEST/MINIMUM?
Longest → shrink WHILE INVALID, update AFTER the while.   Shortest/Minimum → shrink WHILE VALID, update INSIDE the while.
Signal
What "shape" of problem screams sliding window?

The problem talks about a contiguous subarray / substring / run of consecutive elements - not "any subset". Order and adjacency matter.

Signal
What must be true about the window's "value" as it grows/shrinks?

Monotonic window condition - usually because values are non-negative (lengths, counts, positive sums):

  • Expanding the window (move right) only ever makes the tracked value go up / the constraint tighter.
  • Shrinking the window (move left) only ever makes it go down / looser.

If adding an element could make things "better" or "worse" unpredictably (e.g. negative numbers in a sum), the left pointer can't be trusted to move only forward - sliding window breaks down (think Kadane's / DP instead).

2. Core Idea & Template

Two pointers, asymmetric roles: right drives a for loop and always expands (add arr[right] to window state). left moves inside a while loop and shrinks (remove arr[left] from window state).

Shrink WHILE INVALID, update AFTER the while.

let left = 0, maxLen = 0;

for (let right = 0; right < arr.length; right++) {
  // expand: add arr[right] to window state

  while (/* window invalid */) {
    // shrink: remove arr[left] from window state
    left++;
  }

  // window is guaranteed valid here
  maxLen = Math.max(maxLen, right - left + 1);
}

Shrink WHILE VALID, update INSIDE the while.

let left = 0, minLen = Infinity;

for (let right = 0; right < arr.length; right++) {
  // expand: add arr[right] to window state

  while (/* window still valid */) {
    minLen = Math.min(minLen, right - left + 1);
    // shrink: remove arr[left] from window state
    left++;
  }
}
Mnemonic: "Longest waits for the dust to settle, then measures. Shortest measures on the way down."

3. Tricks & Twists

Fixed-size vs Variable-size window

The window length is a known number (given k, or derived like len(pattern)). You slide that exact-size window across and compute something at every position.

Trigger words: "window of size k", "every contiguous subarray of size k", "anagram / permutation of p" (size = len(p)).

Examples:

  • findAllAnagramsInAString
  • permutationInString
  • slidingWindowMaximum
  • slidingWindowMedian

The size is not given; it's part of the answer. Expand right to grow, shrink left when a condition is violated/satisfied.

Trigger words: "longest / shortest / minimum / maximum length ... such that", "smallest substring containing...".

Examples:

  • LongestSubStringWithoutRepeatingCharacter
  • minimumSizeSubarraySum
  • minimumWindowSubstring
  • longestRepeatingCharacterReplacement
  • fruitsIntoBaskets
  • maxConsecutiveOnesIII

Counting "exactly K" windows

Trick

Trigger words: "count subarrays/substrings with EXACTLY K ..." (e.g. exactly K distinct integers, exactly K odd numbers, sum exactly S).

Counting "exactly K" directly is awkward because validity isn't a simple grow/shrink boundary - many sub-windows can independently satisfy it. The fix:

countExactly(K) = countAtMost(K) - countAtMost(K - 1)

countAtMost(K) is a normal variable-size window: for each right, shrink left while the window has more than K of the tracked thing, then add (right - left + 1) to the count - that's the number of valid subarrays ending at right. 

function countAtMost(arr, k) {
  let left = 0, count = 0;
  const window = new Map(); // or a counter, depending on "thing" tracked

  for (let right = 0; right < arr.length; right++) {
    // expand: add arr[right] to window state

    while (/* window has more than k of the tracked thing */) {
      // shrink: remove arr[left] from window state
      left++;
    }

    count += right - left + 1; // all subarrays ending at right are valid
  }
  return count;
}

const countExactly = (arr, k) => countAtMost(arr, k) - countAtMost(arr, k - 1);

Example in this folder: subarraysWithKDistinctIntegers (LC 992). Same trick also solves "Count Number of Nice Subarrays" (LC 1248) and "Binary Subarrays With Sum" (LC 930).

4. Common Pitfalls

Pitfall

Updating the result in the wrong place relative to the while loop: for longest, update after the while (window just became valid); for shortest/minimum, update inside the while (window is still valid). Swapping these gives wrong/missed answers.

slidingWindowMedian

Split the window into two balanced piles: a max-heap for the smaller half, a min-heap for the larger half, kept within 1 of each other in size. The median lives right at the seam between the piles. Removing an old element doesn't rebuild the heaps - it's just marked "delayed" and quietly swept away once it bubbles to the top.

Family: Fixed-size + two-heaps + lazy deletion - the "window state" upgrade for sliding window max when you need the median, not just the max.

"Exactly K" can't be measured by a single grow/shrink boundary - so don't. Count "at most K" windows ending at each right (a normal variable-size shrink-while-invalid window), do it again for "at most K-1", and subtract. What's left is exactly the windows with precisely K distinct values.
